# Changelog 22: v0.6.0 - 16MB Chunked Dual-Buffering Backpressure Pipe (Zero-Disk Large File Streaming)

## 1. Bối cảnh & Vấn đề (Context & Pain Points)
1. **Rào cản tải file lớn qua mạng & Edge Proxy:**
   - Khi truyền tải file dung lượng lớn (từ hàng trăm MB đến nhiều GB) qua Internet hoặc các mạng biên trung chuyển (như Cloudflare Quick Tunnel / Reverse Proxy), các file lớn thường bị cắt đứt do vượt quá giới hạn Request Body tối đa (Cloudflare 100MB body limit) hoặc gây tràn bộ nhớ RAM/đĩa cứng của Server khi buffer toàn bộ file.
2. **Nguy cơ cạn kiệt tài nguyên Server:**
   - Nếu lưu trữ file tạm thời trên ổ cứng server, hàng loạt phiên tải đồng thời có thể gây cạn kiệt I/O và dung lượng ổ cứng.
   - Nếu giữ trong RAM mà không có cơ chế kiểm soát tốc độ (Backpressure Flow Control), Bên Gửi (TX) với mạng nhanh có thể bơm dữ liệu vượt quá tốc độ nhận của Bên Nhận (RX), làm phình bộ nhớ RAM server không kiểm soát.

## 2. Giải pháp Thực hiện (Architectural Implementation)

### 2.1 Chuẩn hóa Khối 16MB & Dual-Buffering (Ping-Pong Pipe)
- **Chuẩn hóa kích thước Chunk**: Cố định $16\text{MB} = 16,777,216$ bytes ($2^{24}$ bytes) tối ưu hóa kích thước trang bộ nhớ và nằm sâu dưới ngưỡng 100MB của Cloudflare Edge.
- **Kênh đệm dung lượng kép (`make(chan *ChunkItem, 2)`)**:
  - Buffer cố định chính xác 2 slots (tối đa $32\text{MB}$ RAM per-session).
  - Hoàn toàn **0 byte ghi đĩa cứng Server** (Zero-Disk Footprint).
  - Go Channel tự động điều tiết tốc độ (Backpressure): Khi buffer đủ 2 chunks, kết nối POST của TX sẽ tự động dừng chờ cho đến khi RX tiêu thụ bớt 1 chunk.

### 2.2 Luồng Đồng Bộ & Kiểm Soát Trạng Thái (Lifecycle & Flow Control)
- **Chunk 0 Tạm Giữ Chờ RX**:
  - TX nạp trước Chunk 0. Nếu RX chưa kết nối, server trả về `{"status": "waiting_rx"}`.
  - Phía TX tạm dừng nạp các chunk tiếp theo, hiển thị `[⏸ CHỜ RX]` trên giao diện.
  - Hẹn giờ tự hủy 10 phút (`ChunkIdleHold = 10m`): Nếu sau 10 phút RX không vào, slot tự động thu hồi và dọn sạch RAM.
- **Tự Động Kích Hoạt Tiếp Nối Khi RX Vào Dây**:
  - Khi RX kết nối (qua Web SSE `partner_paired` / `rx_connected` hoặc HTTP Polling fallback), TX lập tức tiếp tục bơm Chunk 1, 2, ... $N$.
- **Bảo Vệ Đứt Gãy (Stall Timeout & Retry)**:
  - Giới hạn chờ 45 giây (`ChunkStallLimit = 45s`) cho mỗi thao tác `PushChunk` và `PopChunk`.
  - Phía Client hỗ trợ tự động thử lại 3 lần theo lũy thừa 2 (`1s`, `2s`, `4s`) khi mạng biến động.
- **Hủy Bỏ & Dọn Sạch Chủ Động (Abort Pipe)**:
  - Endpoint `POST /{room}-s/abort` cho phép Bên Gửi chủ động hủy phiên tải lên (`[✕ HỦY TẢI LÊN]` hoặc gỡ file), ngay lập tức xả sạch RAM và ngắt kết nối RX.

### 2.3 Phía Bên Nhận (Web Direct-to-Disk Stream & CLI)
- **Web SPA (Direct-to-Disk)**:
  - Tận dụng Native File System Access API (`window.showSaveFilePicker`): Mở hộp thoại chọn nơi lưu và pipe trực tiếp `ReadableStream` xuống ổ cứng thông qua `response.body.pipeTo(writable)`. RAM trình duyệt luôn ở mức 0 MB, không lo giật lag hay tràn bộ nhớ tab.
  - Tự động fallback về luồng tải Native (`<a> download`) trên các trình duyệt không hỗ trợ File System Access API.
- **CLI Receiver**:
  - Tương thích 100% với `curl -sLJO http://.../{slug}-r`: Server xả stream liên tục toàn bộ các chunks tuần tự với `flusher.Flush()`, curl ghi trực tiếp ra file mà không cần thêm bất kỳ script hỗ trợ nào.
