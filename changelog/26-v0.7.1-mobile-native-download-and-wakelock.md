# Changelog 26: v0.7.1 - Tải File Nền Cho Thiết Bị Di Động: Native OS Download, Chống Ngắt Khi Tắt Màn Hình & Screen Wake Lock

## 1. Bối cảnh & Vấn đề (Context & Pain Points)
Khi thử nghiệm tải file trên các thiết bị di động (iPhone / iPad chạy Safari/Chrome WebKit và điện thoại Android chạy Chrome/Samsung Internet), phát sinh lỗi nghiêm trọng:
1. **Quá trình tải file bị dừng ngay lập tức khi tắt màn hình (Off-screen) hoặc chuyển ứng dụng**:
   - Khi người dùng khóa máy, màn hình tắt do timeout, hoặc chuyển sang lướt app khác, tiến trình tải file bị đứng cứng và sau đó báo lỗi đứt kết nối.
2. **Nguyên nhân kỹ thuật gốc rễ (Root Cause)**:
   - **Thiếu API ghi đĩa trực tiếp**: Trình duyệt di động không hỗ trợ `window.showSaveFilePicker` (vốn chỉ có trên Desktop Chromium).
   - **Tích lũy RAM JavaScript (Memory Leak/Bloat)**: Nhánh fallback trước đây dùng `fetch()` đọc stream và dồn toàn bộ dữ liệu vào mảng JavaScript `chunks.push(value)`.
   - **Bộ dọn dẹp bộ nhớ & Đóng băng luồng ngầm của OS**:
     - iOS WebKit và Android Blink đóng băng (suspend) toàn bộ JavaScript execution và bóp nghẹt network socket của tab ngầm chỉ sau vài giây.
     - Với các file lớn (>100MB), việc dồn byte vào heap JS kích hoạt cơ chế diệt tiến trình ngầm của hệ điều hành (**iOS Jetsam Killer** / **Android LowMemoryKiller**), lập tức bắn hạ tab trình duyệt.
     - Trình duyệt chỉ biết đây là file tải về sau khi đọc đủ 100% vào RAM và tạo Blob URL (`a.click()`), lúc đó đã quá muộn.

## 2. Giải pháp Thực hiện (Implementation Details)

Tại phiên bản **v0.7.1**, WireDrop tái cấu trúc toàn diện luồng tải xuống của Phía Nhận (RX) tại [public/app.js](file:///E:/TT/WireDrop/public/app.js) và [public/index.html](file:///E:/TT/WireDrop/public/index.html):

### 2.1 Chuyển Giao Trực Tiếp Cho Trình Quản Lý Tải Về Của Hệ Điều Hành (Native OS Download)
- Tự động nhận diện thiết bị di động qua `isMobileDevice()`.
- Trên Di động (hoặc bất kỳ trình duyệt nào không hỗ trợ `showSaveFilePicker` như Firefox/Safari Desktop):
  - Kích hoạt tải trực tiếp bằng Native Download: `<a href="/${slug}-r?conn=${cid}" download="${fileName}">`.
  - Server WireDrop đã có sẵn chuẩn HTTP headers:
    - `Content-Type: application/octet-stream`
    - `Content-Disposition: attachment; filename="..."; filename*=UTF-8''...`
  - **Hệ quả vượt trội**:
    - Trình duyệt di động lập tức bàn giao quyền tải xuống cho **Download Manager của Hệ điều hành** (iOS Safari Downloads / Android DownloadManager).
    - Socket tải được quản lý độc lập bởi OS Service: **Người dùng có thể tắt màn hình, khóa máy, đút túi quần, hoặc chuyển sang xem YouTube thì file vẫn tiếp tục tải 100% trong nền**.
    - Dữ liệu ghi trực tiếp từng byte xuống thư mục Downloads của máy: **Tiêu tốn 0 Byte RAM JavaScript**, loại bỏ vĩnh viễn nguy cơ crash tab do tràn bộ nhớ.

### 2.2 Đồng Bộ Tiến Độ Thời Gian Thực Qua SSE (`chunk_ack`)
- Dù Native Download được hệ điều hành đảm nhiệm, trang web WireDrop vẫn giữ kết nối SSE `/events`.
- Server mỗi khi xả xong một chunk 8–32MB xuống socket của người nhận đều phát sự kiện `chunk_ack`.
- Web UI phía RX bắt sự kiện `chunk_ack` để cập nhật thanh tiến trình, số mảnh đã nhận và lưới chip visualizer mượt mà.
- Khi server xả xong toàn bộ file, sự kiện `payload_cleared` kích hoạt thông báo `[TẢI VỀ HOÀN TẤT ✓]` trên giao diện.

### 2.3 Khóa Sáng Màn Hình Thông Minh (Screen Wake Lock API)
- Tích hợp `acquireWakeLock()` sử dụng `navigator.wakeLock.request('screen')`.
- Giữ màn hình thiết bị luôn sáng trong suốt quá trình tải nếu người dùng để điện thoại trên bàn theo dõi tiến độ, ngăn máy tự động sleep do không chạm màn hình.
- Tự động lắng nghe `visibilitychange` để tái kích hoạt Wake Lock khi người dùng mở lại màn hình.

### 2.4 Tinh Chỉnh UX/UI Riêng Cho Thiết Bị Di Động
- Trên Mobile, nút hành động tự động đổi thành: **`TẢI VỀ MÁY (CHẠY NGẦM)`** kèm ghi chú an tâm:
  *`⚡ Hỗ trợ tải ngầm: Cho phép tắt màn hình hoặc chuyển app.`*
- Trên Desktop, người dùng vẫn có thể click link phụ: *`Hoặc tải trực tiếp qua trình duyệt (Native)`* nếu không muốn mở hộp thoại chọn thư mục.
