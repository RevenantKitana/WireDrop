# Changelog 23: v0.6.1 - Sửa Triệt Để Lỗi 0-Byte Single-Batch & Dashboard Trực Quan Hóa Đa Mảnh Cho Cả TX & RX

## 1. Bối cảnh & Vấn đề (Context & Pain Points)
1. **Lỗi File 0-Byte khi Tải File $\le 16\text{MB}$ (1 Batch duy nhất):**
   - Khi truyền tải file có dung lượng $\le 16\text{MB}$ (hoặc file nhỏ), file tải về máy tại bên nhận (RX) bị kích thước 0 byte hoặc trình duyệt báo "Unknown size" (thiếu header `Content-Length`).
   - **Nguyên nhân cốt lõi 1 (Server-side Premature Slot Clearing):** Trong `handler_pipe.go` (`handleReceiver`), slot vật phẩm trước đây bị xóa sớm (`room.Slot = PipeSlot{Type: PayloadEmpty}`) ngay khi bắt đầu phục vụ. Khi trình duyệt gửi prefetch request hoặc kết nối lặp lại, slot đã rỗng khiến kết nối tải về thực sự nhận 0 byte.
   - **Nguyên nhân cốt lõi 2 (Server-side Dropped Content-Length):** Khi truyền `PayloadChunkStream` với chỉ 1 chunk duy nhất, việc gọi sớm `flusher.Flush()` kích hoạt Go HTTP server tự động chuyển sang `Transfer-Encoding: chunked` và loại bỏ header `Content-Length`.
   - **Nguyên nhân cốt lõi 3 (Client-side Incomplete Stream Pipe):** Tại Web SPA nhận, phương thức `response.body.pipeTo(writable)` với File System Access API không đảm bảo stream được commit và đóng (`close()`) tin cậy trong một số môi trường Chromium, để lại file stub 0 byte rỗng được tạo bởi `showSaveFilePicker()`.
2. **Bất Cập UX/UI Truyền Nhận File Đa Mảnh (Multi-Batch):**
   - Trước đây chỉ bên gửi (TX) có hiển thị upload đơn giản. Người dùng không thấy được trạng thái luân chuyển của từng mảnh 16MB (Mảnh nào đang nạp, mảnh nào nằm trong RAM đệm, mảnh nào đã chuyển giao).
   - Bên nhận (RX) chỉ có nút bấm tĩnh `[TẢI FILE VỀ MÁY]`. Khi tải các file lớn hàng trăm MB hay hàng GB, người dùng hoàn toàn "mù" tiến trình (không biết đã nhận bao nhiêu MB, tốc độ bao nhiêu MB/s, còn bao lâu nữa thì xong, và không có nút hủy tải chủ động).

## 2. Giải pháp Thực hiện (Architectural Implementation & UX/UI Upgrades)

### 2.1 Sửa Triệt Để Lỗi 0-Byte & Bảo Toàn `Content-Length`
- **Xóa Slot An Toàn Tuyệt Đối (Post-Transfer Slot Clear):**
  - Chỉ dọn dẹp slot (`room.ClearSlot()`) và phát SSE `payload_cleared` **SAU KHI** toàn bộ payload (Text, File, hoặc ChunkStream) đã được stream hoàn tất xuống socket của client mà không gặp lỗi.
  - Sử dụng `RLock()` khi đọc slot tại thời điểm nhận request để chống Race Condition.
- **Bảo Toàn Header `Content-Length`:**
  - Đối với `PayloadChunkStream` có `sess.TotalChunks == 1`, server bỏ qua bước `flusher.Flush()` sớm, giữ nguyên header `Content-Length` chuẩn cho các trình quản lý download của trình duyệt và CLI `curl`.
  - Bổ sung các custom headers: `X-File-Size`, `X-Total-Chunks`, và khai báo mở qua `Access-Control-Expose-Headers` trong `corsMiddleware`.
- **Refactor Cơ Chế Direct-to-Disk Tại Client RX:**
  - Thay thế `pipeTo` bằng vòng lặp điều khiển trực tiếp `reader.read()` tường minh.
  - Đảm bảo `await writable.close()` luôn được gọi trong khối `finally` để commit dữ liệu từ đệm OS xuống file vật lý.
  - Bổ sung cơ chế Fallback Blob Stream mượt mà cho các trình duyệt không hỗ trợ File System Access API.

### 2.2 Thống Nhất Kiến Trúc Chunked Upload (Unified Pipeline)
- Hợp nhất toàn bộ luồng tải file tại Client: Bất kể file $\le 16\text{MB}$ (1 mảnh) hay $> 16\text{MB}$ ($N$ mảnh), tất cả đều đi qua hàm chuẩn hóa `uploadChunkedFile(file)`.
- Loại bỏ phân nhánh code dư thừa, giúp toàn bộ cơ chế đo tốc độ, backpressure, ping-pong RAM và hiển thị trực quan đồng nhất 100%.

### 2.3 Bảng Trực Quan Hóa Đa Mảnh (Visual Batch Grid) Cả 2 Đầu TX & RX
- Bổ sung component `.batch-grid` và `.batch-chip` theo phong cách Retro Monochrome Minimalist:
  - `[✓ Mảnh K]`: Mảnh đã hoàn tất truyền nhận (nền đen chữ trắng).
  - `[⟳ Nạp K]` (TX) / `[⬇ Nhận K]` (RX): Mảnh đang hoạt động với hiệu ứng nhịp thở (`batchPulse`).
  - `[⧖ Đệm K]`: Mảnh đã nằm trong RAM server, chờ RX kéo về.
  - `[Mảnh K]`: Mảnh đang xếp hàng chờ.
- Trên thẻ file đã sẵn sàng (`fileActiveCard` & `recvFileReadyCard`), hiển thị ghi chú cấu trúc file (ví dụ: `Đa Mảnh: 8 mảnh × 16MB` hoặc `1 Mảnh duy nhất (12.4 MB) • Sẵn sàng`).

### 2.4 Bảng Đồng Hồ Tiến Trình Tải Về (RX Download Dashboard)
- Khi bên nhận bấm `[TẢI FILE VỀ MÁY]`, giao diện chuyển sang `recvFileProgressCard`:
  - **Tên file & Thanh tiến trình:** Fill bar hiển thị % trực quan.
  - **Lưới 4 chỉ số thời gian thực (Real-time Metrics Grid):**
    - `TIẾN ĐỘ`: $0\% \to 100\%$.
    - `DUNG LƯỢNG`: Dung lượng đã tải về / Tổng dung lượng (format tự động KB, MB, GB).
    - `TỐC ĐỘ`: Đo lường trượt thời gian thực (ví dụ `18.4 MB/s`).
    - `DỰ KIẾN`: Ước lượng thời gian hoàn thành còn lại (ETA: `1m 24s`).
  - **Batch Grid RX:** Hiển thị vị trí mảnh đang ghi trực tiếp xuống đĩa cứng.
  - **Nút Hủy Tải Về (`[✕ HỦY TẢI VỀ]`):** Tích hợp `AbortController` để ngắt stream an toàn, giải phóng File Handle và reset trạng thái giao diện sạch sẽ.
